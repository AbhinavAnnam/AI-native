# AI-Native Requirements Extraction Pipeline

This project is a working prototype for turning uploaded software requirements documents into structured feature specifications using a Retrieval-Augmented Generation (RAG) approach.

The current implementation focuses on Phase 1 of the workflow:

- upload PDF documents
- split them into chunks
- embed the text using a vector database
- retrieve the most relevant context
- send that context to Gemini for structured requirements extraction
- display the result in a simple frontend dashboard

---

## What this project does

The application is designed to help transform technical specification documents into machine-readable output such as:

- feature names
- target module names
- business rules
- function signatures
- custom exceptions

This is useful for AI-driven code generation pipelines, where requirements must be extracted in a structured, implementation-ready format before a coding agent starts generating code.

---

## Current working architecture

### 1) Backend API

The main backend is in [backend/main.py](backend/main.py).

It exposes a FastAPI service with:

- `POST /api/phase1/extract` — accepts uploaded PDF files and runs the extraction pipeline
- `GET /api/logs` — returns the log output of the pipeline

This is the main working entry point of the project.

### 2) Frontend dashboard

The user interface is in [frontend/app.py](frontend/app.py).

It provides:

- PDF upload input
- one-click “Process Documents & Extract Specs” action
- JSON display of the extracted output
- execution log viewing

This is a Streamlit app meant to act as the project control panel.

### 3) RAG components

The core logic is under [phase1_rag/](phase1_rag/):

- [phase1_rag/parser.py](phase1_rag/parser.py) — parses documents and creates text chunks
- [phase1_rag/embedder.py](phase1_rag/embedder.py) — creates embeddings and stores them in ChromaDB
- [phase1_rag/extractor.py](phase1_rag/extractor.py) — retrieves relevant context and asks Gemini to synthesize structured requirements

### 4) Output artifact

The project writes extracted JSON to:

- [extracted_specs.json](extracted_specs.json)

This is the generated result of the extraction workflow.

## How the pipeline works

The current flow is:

1. User uploads one or more PDF files from the Streamlit UI.
2. The backend receives the files in the FastAPI endpoint.
3. It extracts text page by page using `pypdf`.
4. It chunks the text into smaller document fragments.
5. It creates embeddings and stores them in ChromaDB.
6. It queries the vector store for the most relevant context.
7. It passes the retrieved context to Gemini.
8. Gemini returns a structured JSON response describing features, rules, functions, and exceptions.
9. The API returns the JSON to the frontend and the UI displays it.

## Main implementation details

### Backend endpoint

The main extraction route is in [backend/main.py](backend/main.py):

- it loads environment variables from `.env`
- validates that `GEMINI_API_KEY` exists
- chunks PDF content
- creates a temporary Chroma collection
- generates embeddings using SentenceTransformer (`BAAI/bge-small-en-v1.5`)
- queries the collection
- calls Gemini `gemini-3.6-flash` with a structured JSON schema

### ChromaDB indexing

The vector store logic is in [phase1_rag/embedder.py](phase1_rag/embedder.py):

- persistent database stored under `chroma_db_docs/`
- uses Gemini embeddings via `gemini-embedding-001`
- stores chunks with metadata like source and page
- supports retrieval using query embeddings

### Extraction model behavior

The requirement synthesis logic is in [phase1_rag/extractor.py](phase1_rag/extractor.py):

- retrieves relevant chunks from ChromaDB
- builds a prompt for Gemini
- asks for structured modules/features
- expects fields such as:
  - `project_title`
  - `features`
  - `feature_name`
  - `target_module`
  - `business_rules`
  - `functions`
  - `exceptions`

## Prerequisites

Before running the project, make sure you have:

- Python 3.10+
- a Google Gemini API key
- access to the internet for Gemini API calls
- a local environment that can install Python dependencies

---

## Setup

### 1) Create a virtual environment

```bash
python -m venv .venv
```

Activate it:

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

### 2) Install dependencies

```bash
pip install -r requirements.txt
```

### 3) Add your environment variable

Create a `.env` file in the project root:

```env
GEMINI_API_KEY=your_google_gemini_api_key_here
```

## Run the project

### Start the backend

```bash
uvicorn backend.main:app --reload --port 8000
```

The API should be available at:

- http://127.0.0.1:8000

### Start the frontend

```bash
streamlit run frontend/app.py
```

The UI should open in the browser and allow PDF upload + processing.

Endpoint:

## Common troubleshooting

### Missing Gemini API key

If the backend returns an error about `GEMINI_API_KEY`, make sure your `.env` file exists and contains the key.

### Backend startup fails

Check that dependencies are installed and that the environment is activated.

### UI cannot connect to backend

Ensure the FastAPI backend is running on port 8000 before starting Streamlit.

### No text extracted from uploaded files

Make sure the uploaded file is a valid PDF and not an image-only or corrupted document.
